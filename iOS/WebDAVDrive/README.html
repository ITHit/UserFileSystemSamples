WebDAV Drive Sample for iOS in .NET, C#

This sample implements a virtual file system for iOS that displays documents from a WebDAV server. It uses the iOS File Provider API (NSFileProviderReplicatedExtension, iOS 16+) and exposes the virtual drive inside the iOS Files app.

Requirements

  • .NET 8 SDK with the ios workload (sudo dotnet workload install ios)
  • Xcode 15+
  • iOS 16.0+ device or simulator

Solution Structure

The iOS sample mirrors the macOS sample: a container application registers the File Provider domain and runs the WebSocket remote storage monitor, while the File Provider extension (.appex) implements the virtual file system.

All virtual file system code (VirtualEngine, VirtualFolder, VirtualFile, VirtualFileSystemItem, Mapping) and the remote storage monitor (RemoteStorageMonitorBase, RemoteStorageMonitor, ProtocolParameters) are shared with the macOS sample via linked files.

Shared libraries are built for iOS via companion projects that reference the same sources:

  • Sources/ITHit.FileSystem.Mac/ITHit.FileSystem.Mac.iOS.csproj — engine, targets net8.0-ios. FileProviderUI (FPUIActionExtensionViewController) is macOS-only and excluded. NSDistributedNotificationCenter does not exist on iOS, so the engine posts app↔extension notifications through files in the File Provider shared container (NSFileProviderManager.DocumentStorageUrl) instead — see InterprocessNotification.cs.
  • Samples/macOS/Common/Core/Common.Core.iOS.csproj
  • Samples/macOS/WebDAVDrive/WebDAVCommon/WebDAVCommon.iOS.csproj — excludes AppKit/WebKit auth view controllers and security-scoped bookmark helpers.

Setting License

Set WebDAVClientLicense and UserFileSystemLicense in Samples/macOS/WebDAVDrive/WebDAVMacApp/Resources/appsettings.json (the file is shared with the macOS sample). The Engine can also run without an explicit license for a 5-day trial.

Setting WebDAV Server URL

Set WebDAVServerURLs and WebSocketServerUrl in appsettings.json, or add a server URL in the app UI (+ button).

Running the Sample

  1. Build: dotnet build ../UserFileSystemSamplesiOS.sln
  2. For the iOS Simulator on Apple Silicon Macs use the x64 build (runs under Rosetta) — dotnet build WebDAViOSApp/WebDAViOSApp.csproj -p:RuntimeIdentifier=iossimulator-x64.
    Note: the arm64 simulator build currently fails to link native System.Security.Cryptography symbols inside the File Provider extension; this is a .NET iOS runtime-pack/app-extension interaction and does not affect device builds.
  3. Deploy WebDAV Drive.app to a simulator (xcrun simctl install booted "WebDAV Drive.app") or a device.
  4. In the app, tap a WebDAV server URL to mount it (registers the File Provider domain).
  5. Open the Files app — the drive appears under Locations.

Simulator troubleshooting

  • Extension crashes on launch — the extension project uses the native static registrar (<Registrar>static</Registrar>) and disables the managed debugger (<MtouchDebug>false</MtouchDebug>) to avoid a Mono runtime assertion in the system-launched extension process. It also includes the marshal-ilgen runtime component.
  • Files shows “content unavailable” after reinstalling — the simulator caches the extension path from the previous install. Reboot the simulator to clear the cached service path: xcrun simctl shutdown <uuid> then xcrun simctl boot <uuid> before installing again.
  • Mounting fails with a provisioning/app-group error — the unsigned simulator build does not have a real app group entitlement. The UI and domain registration can still be tested, but the full mount flow requires a signed build with a valid group.com.test.webdavdrive app group.

Testing on a physical iOS device

Testing the full File Provider mount flow on a real device requires an Apple Developer account, signing, and an App Group. The simulator build can list the UI and register the domain, but the shared container between the app and extension is not reliably available without real entitlements.

1. Apple Developer portal setup

  1. Sign in to Apple Developer Center.
  2. Go to Identifiers and create:
    • An App Group with identifier group.com.test.webdavdrive.
    • An App ID with Bundle ID com.test.webdavdrive.app. Enable the App Groups capability and assign it to group.com.test.webdavdrive.
    • An App ID with Bundle ID com.test.webdavdrive.app.extension. Enable the App Groups capability and assign it to group.com.test.webdavdrive.
  3. Register the iOS device(s) you will test on.
  4. Go to Profiles and create an iOS App Development provisioning profile that includes com.test.webdavdrive.app and com.test.webdavdrive.app.extension (multi-app profiles are allowed for development) and your test device. Download and double-click to install it.
  5. Make sure your Mac has a valid iPhone Developer certificate in Keychain Access.

2. Project signing configuration

The Release configuration in both projects is already set up for device signing:

  • WebDAViOSApp/WebDAViOSApp.csproj — CodesignKey=iPhone Developer, CodesignEntitlements=Entitlements.plist, CodesignProvision=Automatic.
  • WebDAVFileProviderExtension/WebDAVFileProviderExtension.csproj — same settings.

You can override these from the command line if you have a specific certificate or provisioning profile:

dotnet build WebDAViOSApp/WebDAViOSApp.csproj \
  -c Release \
  -p:RuntimeIdentifier=ios-arm64 \
  -p:CodesignKey="Apple Development: Your Name (TEAMID)" \
  -p:CodesignProvision="Your Dev Profile Name" \
  -p:CodesignRequireProvisioningProfile=true

3. Deploy and run

Build an .app bundle for the device, then install and launch it. The simplest way is to let dotnet deploy to the connected device:

dotnet build WebDAViOSApp/WebDAViOSApp.csproj \
  -c Release \
  -t:Run \
  -p:RuntimeIdentifier=ios-arm64 \
  -p:CodesignKey="Apple Development: Your Name (TEAMID)" \
  -p:CodesignProvision="Your Dev Profile Name"

A convenience script is provided: build-device.sh. Set TEAM_ID and run it:

export TEAM_ID=ABCD123456
./build-device.sh

Alternatively, build the .app and install it manually with xcrun devicectl or Xcode’s Devices and Simulators window.

4. Test the provider

  1. On the device, open Settings → General → VPN & Device Management and trust the developer.
  2. Open the WebDAV Drive app and tap the WebDAV URL to mount it.
  3. Open the Files app → Browse → WebDAV Drive.
  4. Browse, open, edit, rename, and delete files against the WebDAV server.

5. Common device errors

  • “No valid provisioning profile” — the App Group is missing from one of the App IDs, or the profile does not include the test device.
  • “The entitlements file requires the App Group ...” — the provisioning profile does not include group.com.test.webdavdrive.
  • Files shows “content unavailable” — the extension process may have crashed. Check the device console in Console.app for WebDAVFileProviderExtension crash logs.
